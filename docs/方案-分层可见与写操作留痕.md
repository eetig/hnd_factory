# 方案：分层可见（游客 / 注册用户 / 管理员）+ 写操作留痕

> 依据：`docs/想法-免登录只读与写操作留痕.md`（使用方的两次原话）
> 政策已拍板（2026-10-20，使用方「可以，按你推荐来」）：
> **① 工单/领料/入库/核算四页对注册用户开放只读；② 采购需求详情仍只给 admin。**
> 状态：**方案就绪，暂不实施**。做的时候照本文顺序走即可。

---

## 0. 先讲清一件事：T0 的难点在**前端**，不在后端

- **后端**：读接口**本来就是公开的**（`SaTokenConfigure` 只拦写方法 + 少数 admin 读页）。所以
  "游客能查物料"在服务端**已经成立**，一行不用改。
- **前端**：现在**整个应用**在登录页之后 —— `router/index.js` 的守卫见不到 token 就跳 `/login`。
  ⇒ **T0 真正的改动是"允许匿名进入"**：路由守卫放行、`AppShell` 在未登录时也能渲染、
  侧栏按"是否登录 / 角色"给每一项算三态（可用 / 锁定 / 不显示）。

⚠️ 有一条**不能动**：`api/request.js` 里「401 → 清凭据 + 跳登录」。写操作对匿名者是 **403**（不是 401），
所以这条留着正好 —— 匿名者点写按钮会看到"请联系管理员"，而不是被踢去登录页。

## 1. 三层能力表（决定实现范围）

| 层 | 身份 | 能做什么 |
|---|---|---|
| **T0 游客** | 未登录 | 物料查询、压力容器体积计算（只读） |
| **T1 注册用户** | 已登录，角色 `member`（也含现有的 `team_leader`/`operator`/`guest`） | T0 全部 + **四个台账页只读**（工单汇总/领料汇总/入库汇总/核算）+ 周统计/日报表/储罐液位（只读）+ 设备台账（只读）+ 资料归档（只读+下载） |
| **T2 管理员** | 角色 `admin` | 全部 + 所有写操作 |

**明确不给 T1 的**：采购需求详情（价格与 OA 单号）、文件导入、图片解析、任何新增/修改/删除/上传。

## 2. 导航的三道闸（精确到每一页，已按 2026-10-20 的代码核对）

现在 `NAV_ITEMS` 的 `perm` 只有两种写法：`ADMIN_PERM`，或者**不写**（不写 = **谁都能看，连未登录都能看**）。
这套方案需要三种闸门，所以给每一项补一个 `access` 字段（三选一）：

| access | 含义 | 页面（当前 `perm` 现状 → 目标） |
|---|---|---|
| `public` | 未登录可用（T0） | **物料查询**（本来就无 perm ✓ 不变）、**压力容器体积计算**（无 perm ✓ 不变） |
| `login` | 登录即可（T1） | **工单汇总 / 领料汇总 / 入库汇总 / 核算**（现 `ADMIN_PERM` → 改）；**周统计 / 日报表记录 / 月底储罐液位记录**（现无 perm → 收紧）；**电费预提**（现无 perm → 收紧）；**资料归档**（现无 perm → 收紧） |
| `admin` | 仅 admin（T2） | **采购需求详情**（政策②，保持 `ADMIN_PERM`）、**设备数据维护**（`equipment:edit`）、**文件导入 / 图片解析**（`work_order:import`，二者是写入口） |

⚠️ 两处**要你知情的变化**：

1. **资料归档从"谁都能看"收紧到"登录后能看"**。变更-126 的 Q5 当时定"全员可看"，那是**还没分层**的时代；
   按三层把证照/合同归 T1 更稳妥。想让游客也能看的话，改回来是一行。
2. **四个台账页从 `ADMIN_PERM` 放开到 `login`**（政策①）。⚠️ **但必须核实后端**：
   `SaTokenConfigure.ADMIN_READ_PATTERNS` 里可能已经把这几页的**读接口**也收成了 admin（变更-096 就这么干过）。
   若如此，只改前端会出现"看得见、点进去满屏 403"。**实施第一步先查这张清单**，必要时把对应路径移除。

角色方面：注册用户给新角色 `member`（只读语义的占位；因为 T1 的闸是"登录"而不是"权限位"，
`member` 暂时不需要任何 `*:view`）。**不要**复用 `guest` 当注册用户 —— 名字会和"游客 T0"混。
`member` 绝不给任何 `*:edit` / `*:import` / `*:upload` / `*:delete`；`schema.sql` 的撤权清单里补一行注释说明这一点。

## 3. 自助注册（自愿，不是强制）

**后端**
- `POST /api/auth/register`：`{username, password, realName}` → 校验用户名唯一、密码长度 →
  **角色固定 `member`**（**绝不接受客户端传 role**）→ 插入 `sys_user` → 直接返回 token（注册即登录）。
- **注册开关**：`app.register.enabled`（`application.yml`，默认 `true`；1Panel 环境变量可关）。
  关闭时该接口返回 403 + 「注册已关闭，请联系管理员开通账号」。
- **限流**：同一 IP 每小时最多 3 次注册（防止有人刷账号把 user 表塞满）。

**前端**
- `/register` 页（与登录页同构，三个字段）；登录页加一行「没有账号？注册一个（自愿）」。
- 注册成功后按登录处理（写 token → 跳第一个可见页）。

## 4. 审计（这个想法的核心）

### 4.1 表

`docs/schema.sql` **第 24 步**：`audit_event`

```
id / event(register|login|logout|write_denied|write_ok|locked_clicked) /
username(可空，匿名记 '' ) / ip / user_agent /
method / path / target(表名或文件前缀) / params_digest(参数摘要 hash) /
result(denied|ok) / created_at
索引：idx_created(created_at) / idx_username / idx_event
```

⚠️ **不存参数正文**：资料内容、密码类字段绝不能进审计表；只存"字段名清单 + sha256 摘要"。

### 4.2 拦截（复用，不新写）

- **写操作被拒**：在 `SaTokenConfigure` 那道 `SaRouter...check(r -> StpUtil.checkRole("admin"))` 的
  **失败分支**里发一个事件。**不新写切面判权限** —— 两处判断迟早不一致（变更-096 的教训）。
- **锁定功能被点**：前端调一个轻量接口 `POST /api/audit/locked-click {pageKey}`；
  **每会话每功能只记一次**（前端用 sessionStorage 去重）。

### 4.3 记录（AOP 只负责这一件事）

- 注解 `@AuditWrite("资料归档-新增")` + `@Around` 切面：成功 → `write_ok`；异常 → 记 `write_denied`
  （带上业务异常文案的摘要）。
- **落库不在切面里**：`ApplicationEventPublisher.publishEvent(...)` → `@Async` 监听器写 `audit_event`。
  审计失败只打日志，**绝不回滚业务**。
- **IP**：`X-Forwarded-For` 取第一个，回落到 `request.getRemoteAddr()`（本站在 OpenResty 后面，必须认这个头）。
- **UA**：`User-Agent` 原样存（截断到 255）。
- **username**：`StpUtil.getSession().get("username")`（登录时已写入，见 `AuthServiceImpl`），
  匿名记空串。

### 4.4 保留期

`audit_event` 只增不减会让库慢慢变大：加一个定时任务每天删 **180 天前**的记录（一条 SQL），
并在文档里写明「IP/UA 属个人数据，仅 admin 可查，保留 180 天」。

## 5. 前端：可见但锁定

- `nav/index.js` 给每一项算三态：`available` / `locked` / `hidden`
  - `hidden`：**采购需求详情**对非 admin；写操作入口（导入/解析）对非 admin —— 这些**不显示**（避免误导）
  - `locked`：T1 有、T0 没有的页（四个台账、报表、设备、资料归档）—— **显示但锁定**
- 锁定态样式：`opacity-60` + `text-slate-500`（**不能用 `text-slate-400`**，护栏禁用且对比度不够）
  + `aria-disabled="true"` + `title="注册后可用"`；**读屏必须能读到"锁定"**，不能只靠颜色。
- 点击锁定项 → 弹 `ElMessageBox`：「这个功能需要注册后才能使用」「也可以请管理员开通账号」+「去注册」。
- 403 文案统一：`request.js` 里拦 `status === 403` → 提示「此操作需要管理员，请联系管理员」（一处改，全站生效）。

## 6. 实施顺序（每步都能单独上、单独回滚）

1. `schema.sql` 第 24 步：`audit_event` 表 + `member` 角色（**只改库**）
2. 后端：注册接口 + 注册开关 + 限流
3. 后端：审计（表 + 事件 + `@AuditWrite` + 403 钩子 + IP/UA）
4. 前端：**开放匿名进入**（路由守卫 + AppShell）+ 侧栏三态 + 锁定交互 + 403 文案
5. 前端：注册页 + 登录页入口
6. （可选）管理端：审计查询页、用户管理页（开通/停用）

## 7. 验收（怎么算做完）

1. **不登录**打开站点：能看到侧栏，物料查询/体积计算可用，点四个台账是锁定态；
2. 不登录点"新增资料"（若可见）= 403 提示「请联系管理员」，且 `audit_event` 出现一条 `write_denied`（IP 正确）；
3. 注册一个账号 → 立刻能进四个台账页（只读）、资料归档能下载，**看不到**采购需求详情；
4. 用注册账号调写接口 → 403 + 一条审计；用 admin 调 → 成功 + 一条 `write_ok`；
5. 审计项**不含**参数正文，只有摘要；`username` 匿名时是空串、IP 不是空的；
6. 关掉注册开关后，注册接口返回 403 且前端给出可读提示。

## 8. 风险与注意

- ⚠️ **最大风险是"放开匿名进入"**：一旦匿名能进，就要求**所有读接口**都是安全的 ——
  目前采购读接口已是 admin-only ✓，但**新增读接口**时必须有意识地问一句"这个能匿名看吗"。
  建议在 `docs/` 里补一条约定：**新读接口默认要能匿名**，否则必须进 `ADMIN_READ_PATTERNS`。
- ⚠️ **审计表会变大**：保留期任务必须有，否则一年后几百万行。
- ⚠️ **IP 在反代后不真实**：必须认 `X-Forwarded-For`，并在 OpenResty 上**只在最外层**设置它
  （否则客户端可以伪造）。
- ⚠️ **别把锁定态做成"看得见摸不着"的钓鱼式设计**：锁定项要有一句人话说明"注册即可用"，
  否则使用者会以为系统坏了。
