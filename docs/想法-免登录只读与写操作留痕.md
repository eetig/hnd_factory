# 想法：分层可见（游客 / 注册用户 / 管理员）+ 写操作留痕（未实施）

> 记于 2026-10-20 初稿；同日按使用方的**分层设想**重写
> 状态：**一个想法，暂不做**（使用方原话：展示不打算做，但担心忘记）

## 使用方原话（两次，第二次澄清了目的）

> 「默认不需要登录，可以使用所有功能，但是遇到增删改数据库或是文件库的操作，会提示联系管理员。
> 而且此次操作会被记录。…记录谁？用户名（所以要新增一个注册功能）和IP。
> …是不是涉及 AOP 或是钩子，这样效果更高，还是我已经落伍了…」

> 「**为什么要注册呢，因为我不想强制别人注册**，看能不能这样：游客可以使用部分功能（你来推荐哪些），
> 其他不能使用的可见，但是颜色淡化，不可点击，如果点击就提示注册。注册用户可以使用所有功能，
> 但是增删改数据库的操作会反馈提示联系管理员。**这样就可以记录登录人了，而且要记录 IP**。」

⇒ **目的不是"卡人"，是"留痕"**：注册是**自愿**的，愿意留名的人能用到全部只读功能；
不愿注册的人照样能用一部分 —— 而**一旦有人越界**，系统至少能记下"匿名 + IP"或"某某 + IP"。

## 一、三层能力（逐页推荐）

### T0 游客（免登录，任何人）—— 只放"离了登录也敢给外人看"的

| 页面 | 给不给 | 理由 |
|---|---|---|
| **物料查询** | ✅ 给 | 查编码/名称/库存，是最典型的"随手查一下"；数据是内部物料清单，不含价格与合同 |
| **压力容器体积计算** | ✅ 给 | 纯计算器，不读写任何业务数据，**风险为零** |
| 设备台账 | ❌ | 含图纸与标定底图，内部资料，放 T1 |
| 其余全部 | ❌ | 见下 |

### T1 注册用户（**自愿注册**，注册后立即生效）—— 全部**只读**

| 页面 | 给不给 | 备注 |
|---|---|---|
| 物料查询 / 体积计算 | ✅ | 与游客相同 |
| **工单汇总 / 领料汇总 / 入库汇总 / 核算** | ✅ **只读** | ⚠️ **这四页现在是 admin 专属**（`NAV_ITEMS` 里 `perm: ADMIN_PERM`）。放开给注册用户读 = 一个**政策决定**，不是纯技术改动 |
| **周统计 / 日报表记录 / 储罐液位记录** | ✅ 只读 | 班组自己看数据，合理 |
| **设备台账** | ✅ 只读 | 含图纸；对内部注册用户可看 |
| **资料归档** | ✅ **只读 + 下载** | 变更-126 的 Q5 就是"全员可看"；有证照/合同，但都是内部资料，注册用户可看 |
| **采购需求详情** | ❌ **仍是 admin** | 它带采购价格与 OA 单号，两天前（变更-096/097）刚按使用方要求改成"只有管理员能看"。**建议不动** —— 如果确实要给注册用户，单独说一声 |
| 文件导入 / 图片解析 | ❌ | 写操作入口，归 T2 |
| 所有"新增 / 修改 / 删除 / 上传"按钮 | ❌ | 归 T2；点了就弹「此操作需要管理员，请联系…」 |

### T2 管理员 —— 全部 + **所有写操作**

写操作保留现状：`SaTokenConfigure` 已有一道集中闸门（非 admin 的 POST/PUT/PATCH/DELETE 一律 403），
所以这一层**一行代码都不用加**，只是文案要更清楚（现在只说"无权限"）。

## 二、"可见但锁定"的交互（使用方明确要的形式）

- 侧栏**不隐藏**这些页：`aria-disabled="true"` + 文字/图标降一档（具体用什么类见下面那条 ⚠️）
  （⚠️ 本项目护栏**禁用** `text-slate-400`（对白底 2.56:1 不过 AA）⇒ 锁定态用 `text-slate-500` + `opacity-60`，
  不要为了"淡化"破掉对比度规则）
- 点击 → 一个对话框：「这个功能需要注册后才能使用」「注册只需一次，也可以请管理员开通账号」+ 一个「去注册」按钮
- **锁定态也要能被读屏读到**（`aria-disabled` + 说明文字），不能只靠颜色

## 三、审计要记什么（这才是这个想法的核心）

| 事件 | 记什么 |
|---|---|
| 注册 | username / 时间 / **IP** / UA |
| 登录 / 登出 | username / 时间 / IP / UA |
| **写操作被拒（403）** | username（或 anonymous）/ IP / UA / 方法 / 路径 / **目标（表或文件前缀）** / 参数摘要 / 时间 |
| **点击锁定功能** | 同上（anonymous）/ 点了哪个功能 / IP / UA |
| 写操作成功（admin） | 同上 + 结果 ok |

⚠️ 三条分寸（免得出事）：

1. **别记每一次点击** —— "点击锁定功能"每会话每功能**只记一次**，否则一次乱点刷出几十条，表会废掉。
2. **参数只存摘要**（hash 或字段名清单），不存正文：资料内容、密码类字段绝不能进审计表。
3. **IP + UA 是个人数据**：只给 admin 看，写清保留期（建议 180 天，到期删）。

## 四、技术上怎么做（回答"是不是 AOP，我落伍没"）

**你没落伍。** 但问题里混了两个词：

- **「钩子」** 是前端框架的生命周期概念（Vue 的 onMounted 之类）—— 它**管不到数据库写**。
- **AOP** 是对的 —— 但**别用它做"拦截"**：你已经有 `SaTokenConfigure` 一处集中闸门，
  再写切面判"是不是 admin" = 两处判断，迟早不一致（变更-096 权限收紧时就踩过这条路）。

**推荐分工**：

| 职责 | 放哪 |
|---|---|
| 拦截（能不能写） | 保留在现有闸门（一处） |
| 记录（谁想写） | `@AuditWrite("资料归档-新增")` 注解 + 一个 `@Around` 切面 |
| 落库 | **不要在切面里同步写表** —— 发 Spring 事件，由 `@Async` 监听器写审计表（审计失败不连累业务） |

"前沿有没有更好的"：有，但都是在套上加固，不是换掉 —— **事件驱动 + 异步**（推荐）、
**outbox 表**（要求审计绝不丢时）、**OpenTelemetry**（那是看性能/链路的，不是业务审计）、
**DB 触发器**（记不到"谁 + IP"）。⇒ `AOP + 注解 + 异步事件`，2026 年依然是标准做法。

## 五、新增的东西（真要做时的清单）

1. `sys_user` 支持**自助注册**（默认角色 = 新增的 `member`；不能自选角色）+ 注册页
2. 注册开关（管理员可一键**关闭注册** —— 内网工具常有这个开关）
3. 角色 `member` 的权限位：只读那些 `*:view`（**不含** `purchase:view`，采购仍 admin）
4. `audit_write_attempt` 表（`docs/schema.sql` 第 24 步）
5. 闸门里"403 时发事件"（一行）
6. 前端：锁定态 + 注册页 + 403 文案统一成「此操作需要管理员，请联系…」
7. （可选）管理端"审计查询"页 + "用户管理"页（开通/停用账号）

## 六、和现有设计的关系 / 要拍板的两件事

- 与 **变更-126 Q5（资料归档全员可看）** 一致：读放开、写管住、越权有痕。
- 与 **ADR-0005** 不冲突（那是数据归属，这是操作留痕）。

**需要你拍板的两个政策问题**（不是技术问题）：

1. **工单/领料/入库/核算 四页要不要对注册用户开放只读？** 它们现在是 admin 专属。
   我倾向：**开放只读** —— 班组看自己的数据本来就应该，而且注册后有 username，责任可追。
2. **采购需求详情要不要给注册用户？** 我倾向：**不给**（价格 + OA 单号，两天前刚定成只有管理员能看）。
