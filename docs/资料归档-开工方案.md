# 资料归档 · 开工方案

> 定稿 2026-10-19　状态：**待实施**（使用方晚上回家开工）
> 起因（使用方原话）：「我们是一家化工厂，目前的痛点是资料没人归纳整理，也就是没有资料员，
> 我想在 hnd-factory 添加一个资料归档的功能。目前没有头绪，因为本人并没有从事过资料员的工作。」
> 本文三块：**已定的 6 条**（照做即可）、**还没定的 5 条**（带推荐，可回"全按推荐"）、**实施顺序与验收**。

## 一、已定（2026-10-19 使用方确认「可以，全都按推荐来」）

| # | 决策点 | 定下来的 | 为什么 |
|---|---|---|---|
| Q1 | 最先解决哪件痛 | **检查时找得到 + 到期能提醒**；纸质原件位置用**一个字段**记，不单独做功能 | 检查最痛且可验收；到期是化工厂特有、最容易出事故；原件位置不需要额外功能 |
| Q2 | 第一版范围 | **台账 + 上传 + 检索 + 到期提醒**。**不做**：审批流、借阅登记、OCR/全文检索、版本管理、扫码归档 | **没有资料员 ⇒ 流程越少越能落地**；审批流/借阅登记会立刻变成没人点的按钮 |
| Q3 | 分类体系 | **两级分类，类目存数据库由使用方维护**。初始 7 大类：证照资质 / 安全环保 / 设备与图纸 / 质量与检验 / 台账记录 / 合同与采购 / 人员与培训 | 分类是资料员的第一件事；没有分类，一年后又回到"没人整理"；各厂类目差异极大，写死必错 |
| Q4 | 必填字段 | **只有 3 个：名称、分类、文件**。选填：有效期至、原件在哪、编号/文号、责任人、备注 | 必填一多就没人录（变更-085 踩过"字段必填、结果 92 行空着"）；但"有效期"和"原件在哪"是检查时最常被问的两句，必须**存在**、不必**必填** |
| Q5 | 权限 | **全员可看可下载**；`archive:edit` 才能增改；**只有 admin 能删**（软删留痕、文件不物理删） | 不做部门隔离——没有资料员时，隔离会变成"谁都看不见"，而检查时最需要"谁都能立刻打开" |
| Q6 | 文件存哪 | **复用现有 MinIO，新开 `archive/` 前缀** | 与现有图片共用一套备份与权限；**这是必须新增的通路**（见下方事实 1） |

### 已经查证的既成事实（不用再问）

1. **现在唯一能存文件的通路是 file-service，而且只收图片**（`ImgController` 只认 `image/*`，
   还会把内容**重编码成 PNG**）⇒ **PDF / Word / Excel 目前根本存不进系统** ✗
2. 现有"文件类字段"只有 5 处：`equipment_ledger.image_file`、`work_order_image.file_name`、
   `tank_level_image.file_name`、`material_pick_summary.file_name`、`production_inbound.file_name`
   —— 后两个**只有文件名、没有文件本体**。
3. 权限走**权限位**（`purchase:edit` 那一套），迁移写在 `docs/schema.sql` 的编号步骤里。
4. 部署：后端 `gradlew bootJar` → 换 jar 重建镜像；前端 `npm run build` → 传站点目录。

## 三、数据模型（初版草案，实施时可微调）

```sql
-- 分类（两级：parent_id 为空 = 大类）
CREATE TABLE `archive_category` (
  `id`          bigint       NOT NULL AUTO_INCREMENT,
  `parent_id`   bigint       NULL COMMENT '为空 = 大类',
  `name`        varchar(64)  NOT NULL,
  `sort_no`     int          NOT NULL DEFAULT 0,
  `created_at`  datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_parent` (`parent_id`),
  UNIQUE KEY `uk_parent_name` (`parent_id`, `name`)
) COMMENT '资料分类（两级，使用方自行维护）';

-- 台账
CREATE TABLE `archive_document` (
  `id`          bigint       NOT NULL AUTO_INCREMENT,
  `name`        varchar(128) NOT NULL                COMMENT '资料名称（必填）',
  `category_id` bigint       NOT NULL                COMMENT '分类（必填）',
  `file_name`   varchar(128) NOT NULL DEFAULT ''     COMMENT 'MinIO archive/ 下的对象名；空 = 只有纸质',
  `orig_name`   varchar(255) NOT NULL DEFAULT ''     COMMENT '原文件名（下载时还原）',
  `file_size`   bigint       NOT NULL DEFAULT 0,
  `mime_type`   varchar(128) NOT NULL DEFAULT '',
  `expire_date` date         NULL                    COMMENT '有效期至（证照/校验/培训类）',
  `origin_place` varchar(128) NOT NULL DEFAULT ''    COMMENT '纸质原件在哪：部门/柜子',
  `doc_no`      varchar(64)  NOT NULL DEFAULT ''     COMMENT '编号/文号',
  `owner`       varchar(64)  NOT NULL DEFAULT ''     COMMENT '责任人',
  `remark`      varchar(500) NOT NULL DEFAULT '',
  `deleted`     tinyint      NOT NULL DEFAULT 0      COMMENT '软删：只有 admin 能删',
  `created_by`  varchar(64)  NOT NULL DEFAULT '',
  `created_at`  datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_category` (`category_id`),
  KEY `idx_expire` (`expire_date`),
  KEY `idx_name` (`name`)
) COMMENT '资料台账';
```

约定（与现有表保持一致）：
- 可选字符串一律 `NOT NULL DEFAULT ''`（MySQL 唯一键不约束 NULL）
- **不建业务唯一键**（同一份资料可能有多册/多年，先按流水账）
- 分页查询的 `ORDER BY` 末尾必须带唯一 `id`
- 软删：`deleted = 1`；文件**不物理删**

## 四、后端要做的事

| 项 | 内容 |
|---|---|
| 上传通路 | `file-service` 新增 `POST /api/file/upload`（**原样存**，不重编码）+ `GET /api/file/{name}` 下载 + `DELETE /api/file/{name}`；对象键前缀 `archive/` |
| 端点 | `GET /api/archive/list`（分页 + 关键词 + 分类 + 到期区间）、`GET /api/archive/category/tree`、`POST /api/archive/save`、`DELETE /api/archive/delete`（admin）、`POST /api/archive/upload`、`GET /api/archive/download/{id}` |
| 权限 | 新权限位 `archive:edit`，加进 `docs/schema.sql` 的授权段与撤销段（与 `purchase:edit` 同一套写法） |
| 到期 | `GET /api/archive/expiring?days=30` 给首页卡片用 |
| 事务 | 写多张表的方法带 `@Transactional(rollbackFor = Exception.class)`（仓库既有约定）；换文件/删记录要**成对**处理存储侧旧文件，且**只认自己前缀**的对象名 |

## 五、前端要做的事（Vue 3 + Element Plus，沿用 x-minimalist）

- 入口：**工具 → 资料归档**（与"采购进度跟踪"同级）
- 布局：**左侧分类树 + 右侧列表**；顶部一个搜索框（名称/编号/责任人）+ 一个"只看 30 天内到期"开关
- 列表列：名称 / 分类 / 有效期（到期红点）/ 原件在哪 / 责任人 / 文件（下载）/ 操作
- 新增与编辑：**行内录入**那套（与采购页 变更-092 一致，不弹窗）
- 上传：选文件即传（进 `archive/`），显示原文件名 + 大小；可替换、可清除
- 首页：加一张「30 天内到期」卡片

## 六、验收标准（做到这几条就算完成）

1. 能新建两级分类，能改能删（大类下有资料时不许删）
2. 能上传 **PDF / Word / Excel / 图片** 并原样下载（下载回来的字节与上传时一致）
3. 必填只有名称/分类/文件（或"纸质"标记）；其余留空能保存
4. 关键词 + 分类 + "只看 30 天内到期" 三个条件能组合筛
5. 非 admin 看不到删除按钮，直接调接口也删不掉（401/403）
6. 首页「30 天内到期」卡片条目数与列表筛选结果一致

## 七、实施顺序（建议，不是工期承诺）

1. `docs/schema.sql` 加两张表 + `archive:edit` 权限位（第 20 步）
2. `file-service` 的原样存取端点（先本地自测上传→下载字节一致）
3. `hnd_factory` 的实体/Mapper/DTO/Service/Controller + 单测
4. 前端页面 + 守卫用例（与 `visualTokens.spec` 同风格）
5. 迁移生产 → 部署两端 → 用真实一份 PDF 走一遍上传/下载/到期筛选

## 八、⚠️ 回家开工前**必须先做**的事（另一台电脑上有未提交的改动）

**在另一台电脑上，先别敲 `git pull` / `checkout` / `reset`** —— 这三个都可能吃掉未提交的改动。

1. **保险**：把整个项目文件夹压成 zip 拷到 U 盘（`.git` 在文件夹里 ⇒ 历史 + 未提交改动全在里面）
2. **看清现状**（只读）：`git status` / `git branch --show-current` / `git log --oneline -3`
3. **推成远端新分支**（不动 `x-minimalist`，绝对安全）：
   ```
   git add -A          # 先看一遍 git status，确认没把 .env / 导出文件加进来
   git commit -m "wip: 另一台电脑上的未提交改动"
   git push -u origin HEAD:wip/<电脑名或日期>
   ```
4. 把 **wip 分支名**发给我，我在这边合并 + 跑门禁 + 处理冲突（**别在另一台上手工解冲突**）。
