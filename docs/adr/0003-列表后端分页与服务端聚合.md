# ADR-0003：列表一律后端分页，聚合由服务端算

- **状态**：已采纳（2026-10-10，变更-035）
- **背景**：列表接口原先「全量返回，日期筛选/排序/分页由前端本地完成」。后果是前端持有一份
  「页面打开那一刻」的快照：图片识别入库之后回到列表页，无论怎么改筛选条件都看不到新记录，
  非重启不可。数据量涨上来后，首屏还要传全表。
- **决定**：
  1. 列表接口一律**后端分页**（`pageNum` / `pageSize` **必传**，缺参回 400 —— 理由见 `PageQueryDTO`）。
  2. 筛选（日期区间 / 物料 / 单据号 / 关键字）与排序都落到 SQL 侧；
     中文名排序用 `CONVERT(name USING gbk)` 近似拼音序，`id` 兜底保证顺序唯一确定。
  3. 前端不再持有全量数据，因此**候选值**（如物料名称下拉）与**聚合**（按物料汇总领料数）
     都必须由服务端按同一套筛选条件给出。
- **后果**：
  - 每加一个「从全量数据里现算」的前端功能，都要先问「分页之后它还成立吗」。
  - 排序口径与 `Collator` 在个别汉字上可能不同；若业务坚持等价，需要在 SQL 层另找方案，
    不要退回内存排序（内存排序会让每页顺序互不一致、甚至漏行重行）。
  - 双源合并 SQL（库存汇总 `stockUnion`）的 records 与 `COUNT(*)` 必须用同一段筛选，否则页码与总数不一致。

> 相关：变更-035、`PageQueryDTO`、`MaterialPickController`、`MaterialStockMapper.xml`。
