# ADR-0001：单据行的唯一键包含日期

- **状态**：已采纳（2026-10-02，变更-047）
- **背景**：领料汇总 / 生产入库的「同一行」原本按 `单据号 + 物料编码` 判定。实际业务里同一张单据
  同一种物料**会在不同日期各有一行**（分批领料/分批入库）。按两列判定会把不同日期的行挤成一条，
  重发一次导入就会互相覆盖、也只留下一行。
- **决定**：行身份 = `单据号 + 物料编码 + 日期`。库层用唯一键钉住
  （`uk_document_no_material_date`），应用层用 `DocMaterialDateKey` 生成同一个 key，
  单据级操作（插入/载入编辑/整单跳过）都按这个 key 对齐。
- **后果**：
  - 日期成为业务必填项：缺日期无法定位行，各 `*ImportUtil.validate` 会报「日期…」类错误。
  - 历史脏数据（日期为 NULL 的行）必须在选择时给出确定顺序 —— `DocumentDiffPlanner` 取 id 最小者，
    否则「判成更新还是不更新」会随查询顺序漂移（有单测钉住）。
  - **改这个键等于改数据契约**：评审再来问「能不能按两列」时，请先读本条。

> 相关：`docs/schema.sql`（唯一键）、`DocMaterialDateKey`、`DocumentDiffPlanner`、变更-047。
