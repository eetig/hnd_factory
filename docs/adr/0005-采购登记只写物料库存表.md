# ADR-0005：采购登记只写 `material_stock`，专用 0000 档，不碰 SAP 主数据

- **状态**：已采纳（2026-10-16，变更-091）
- **背景**：使用方要给采购需求记录物料名称与编码，并要求「以后按编码能查到」；
  设想是「把 `material_stock` 当作物料编码总表：新增编码可以存进来，旧的编码就算库存为 0 也保留」。
  动手前查清了三件事，每一件都改变了做法：

  1. **`material_master` 不是通用物料总表，而是 SAP 物料主数据**（使用方 2026-10-16 澄清：
     「这个是跟SAP系统有关的物料，所以单独做了个表」）。它由 SAP 侧导入 + 手工维护，
     图片解析按名称反查编码/单位走的就是它。**往里写采购登记会污染它**，也会干扰那条反查通路。
  2. **SAP 源数据里物料编码本来就不唯一**：`material_master` 实测 246 行 / **241** 个编码，
     5 个编码各对应两个**真实不同**的物料 ——
     `220000469/470/471/472` 分别是 1000/500/250/100ml 氟化塑料瓶，却共用同一个「外贸」编码；
     `114002501` 同时是「HND-2171前馏份」与「HND-2171过渡馏份」。
     所以「保证物料编码唯一」**不能靠加唯一约束实现** —— 那会丢掉真实信息。
     现表的唯一键是 `uk_code_name (material_code, material_name)`，正是为了容纳这件事。
  3. **`material_stock` 的行身份是 `(plant_code, material_code, storage_location)`**
     （唯一键 `uk_plant_material_location`），而 1503 的真实库位只有
     9001 五金仓 / 1001 原材料仓 / 3001 包材仓 / 9301 安环物资仓 / 2001 乳液成品仓 ——
     **0000 是空的**。它自带的导入语义是「清零只清数量、保留行」。

- **决定**：

  1. 采购记录的物料名称与编码按**快照文本**存在 `purchase_tracking` 自己表里（不是外键）：
     历史单据要能独立读懂，也不该被后来的主数据改名影响。
  2. 保存采购记录时，把编码**只登记进 `material_stock`**：固定 `plant_code=1503`、
     `storage_location=0000`、`storage_desc='采购登记（无库存）'`、`stock_qty=0`，带上名称与规格。
     **不写 `material_master`。**
  3. **该编码在 `material_stock` 里已存在（任何库位）就跳过** —— 它已经能查到了。
     0000 档因此含义明确：「库存表里还没有、由采购登记补进来的编码」。
  4. **不加「物料编码全局唯一」约束**：非 SAP 的采购编码在 0000 档下由唯一键**天然一码一行**
     —— 2026-10-16 在生产库的**事务内实测**：同键第二次插入报
     `ERROR 1062 Duplicate entry '1503-ZZ-TXN-PROBE-001-0000' for key 'material_stock.uk_plant_material_location'`，
     随后 `ROLLBACK`，复核 0000 档回到 0 行、探针行 0 行（**一行测试数据都没留下**）。
     所以使用方「按编码查得到、不重复」的需求由**表结构**满足，而 SAP 那 5 条重码原样保留。
  5. **删除采购记录不回滚登记行**：登记的是「这个编码存在过」，与某一条记录在不在无关 ——
     与「旧编码即使库存为 0 也保留」同一条口径。
  6. 采购表本身**不加唯一键**（采购是流水账，同一物料在不同需求批次里本来就会重复出现），
     只建 编码 / 采购订单号 / 提出需求日期 三个普通索引。
     ⚠️ 这一条是**默认取值，使用方尚未表态**；若将来要收紧成「同一需求日期 + 同一编码只能一条」，
     那属于加约束，**必须先对账历史行**（同第 17) 步回滚段的教训：旧键装不下的数据会让
     `ADD UNIQUE KEY` 直接失败）。

- **后果 / 残留风险**：
  · 0000 档的行会被下一次库存导入清零（该导入既有语义是「清零只清数量、保留行」），
    因此登记行的库存**永远是 0**：它只承担「编码可查」这一个职责，**不是库存数据**，
    查库存时要按库位把它排除或单独看。
  · 采购记录里没有「单位」这一列，所以 0000 档行的 `unit` 为空（不瞎填）。
  · 「一个编码对应两个物料」在总表里表现为**两行不同名称**：这是数据事实，
    界面与查询要能显示多行，**不要**断言唯一。
  · 采购页新增编码后，该编码在「物料查询」页会以 0000 库位出现（库存 0）；
    若使用方觉得碍眼，那是**显示层**过滤的事，**不要**因此改成"不登记"。
