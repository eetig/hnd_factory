# ADR-0004：图片 URL 固定拼接，不用 MinIO 预签名 URL

- **状态**：已采纳（变更-001 时期，2026-10-16 收敛到一处实现）
- **背景**：早期列表/详情里的图片 URL 是后端调 img-service / MinIO 取**预签名 URL**。
  两个后果：① 预签名 URL 每次调用都带新的 `X-Amz-Date`，而浏览器按 URL 缓存 —— URL 一变
  整页图片重下；② 列表组装时对每张图发一次远程调用，列表越翻越慢。
- **决定**：图片 URL 由后端**纯字符串拼接**：`{image.base-url}/files/{fileName}`（原图）、
  `/thumbs/{fileName}`（缩略图）。`image.base-url` 留空表示与前端同源部署，前端拿到相对路径
  （契约 2.3）。拼接规则只有一处实现：`component/ImageUrlBuilder`。
- **后果**：
  - 图片桶**不能**设成私有 + 只靠预签名访问；Nginx（`/files`、`/thumbs`）与桶策略要按
    「可被固定 URL 读取」来配 —— 这是部署侧的前提，代码侧无法兜底。
  - 文件名为空时返回 `null`，前端按 null 处理（不要拼出 `/files/null` 让浏览器下载 404）。
  - 这条理由原先散在 5 个 Service 的注释里；现在只在 `ImageUrlBuilder` 的类注释里。
    不要再往 Service 里复制 `toUrl` / `toThumbUrl`。

> 相关：变更-069（收敛到 `ImageUrlBuilder`）、`ImageUrlBuilderTest`。
