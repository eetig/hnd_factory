# ADR-0002：可编辑列用 `updateStrategy = ALWAYS`，更新路径是整行覆写

- **状态**：已采纳（2026-10-15，变更-061 / 变更-065）
- **背景**：维护页要能**把某列清空**（典型：立式容器改成「平底」，要把下封头深度写成 NULL）。
  MyBatis-Plus 默认策略会跳过 null 字段，于是「页面上清空了、库里没动」——只有清空这一种操作会中招，
  极难发现。另一方面，一旦给可编辑列标上 `ALWAYS`，「半实体 + `updateById`」的写法就会把这些列
  一并放进 SET，半实体里没赋值的列会被写成 `NULL`：撞 NOT NULL 约束时整页操作失败（2026-10-15 实测，
  前端只看到 403，真实原因被 Sa-Token 上下文异常盖掉）。
- **决定**：
  1. 台账的 16 个可编辑列全部标 `@TableField(updateStrategy = ALWAYS)`，清空语义得以生效。
  2. 更新路径保持**整行覆写**：调用方必须带齐全部可编辑字段；改成「只写非 null 字段」会让
     已上线的清空操作静默失效，比现状更糟。
  3. 相应地加两道护栏：三个 NOT NULL 列在服务端先校验（给业务文案而不是 DB 约束异常）；
     `updateById` 影响 0 行时明确报错（原先静默当成功）。
  4. **停用/启用走定向 UPDATE**（只 SET `enabled`），不用半实体 + `updateById`。
  5. 可编辑字段清单是数据（`EquipmentLedgerServiceImpl.EDITABLE_FIELDS`），与 DTO 字段集、
     实体 ALWAYS 列集由单测做三方相等校验。
- **后果 / 残留风险**：区分「没传字段」与「传了 null」需要改 DTO 契约（`JsonNullable` / Map），
  属接口变更，另行评估。**不要**为了「省字段」把整行覆写改回半实体 —— 那正是 变更-061 的事故形态。

> 相关：变更-061、变更-065、`EquipmentLedger`、`EquipmentLedgerServiceImpl`、`EquipmentSaveDTO`。
